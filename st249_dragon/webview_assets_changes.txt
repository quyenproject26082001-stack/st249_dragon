Tổng hợp thay đổi từ trước đến nay của cụm Dragon WebView / assets
=================================================================

Phạm vi tài liệu
- Tài liệu này chỉ ghi lại các thay đổi liên quan đến WebView, JS, HTML, CSS và các file native bridge đi kèm.
- Trọng tâm là luồng Dragon builder, preview, random, edit, download và đồng bộ state.


1. Giai đoạn đầu: dựng Dragon builder bằng assets local

Các file chính
- `app/src/main/assets/index.html`
- `app/src/main/assets/style.css`
- `app/src/main/assets/builder.js`
- `app/src/main/assets/parts_config.json`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`

Những gì đã định hình
- Dùng `index.html` làm giao diện chính cho Dragon builder trong WebView.
- Giao diện ban đầu gồm:
  + top bar
  + preview area
  + action row
  + panel area
  + bottom tabs
- `style.css` phụ trách toàn bộ phần nhìn của WebView.
- `builder.js` là logic chính:
  + load dữ liệu
  + render panel theo tab
  + update preview
  + đổi style / đổi màu / random / reset
- `parts_config.json` chia part theo các tab `head`, `torso`, `legs`, `wings`, `tail`.
- `DragonWebViewActivity` dùng asset loader để load toàn bộ nội dung từ assets local.


2. Giai đoạn nối native Android với JS trong WebView

Các file liên quan
- `app/src/main/assets/builder.js`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonBridge.kt`

Những gì đã thay đổi
- Native Android điều khiển JS qua `window.dispatch(...)`.
- JS hỗ trợ các action:
  + `SET_STYLE`
  + `SET_COLOR`
  + `RANDOMIZE_TRAITS`
  + `RANDOMIZE_COLORS`
  + `RANDOMIZE_ALL`
  + `SET_TAB`
  + `RESET`
  + `GET_STATE`
  + `CAPTURE_FOR_EDIT`
  + `CAPTURE_FOR_SUCCESS`
  + `DOWNLOAD`
- `DragonWebViewActivity.kt` gửi các action từ native sang JS.
- `DragonBridge.kt` nhận event từ JS trả về Android.

Các event JS -> Android đã dùng theo thời gian
- `DOWNLOAD_READY`
- `EDIT_READY`
- `SUCCESS_READY`


3. Giai đoạn lưu state để edit lại đúng Dragon

Các file liên quan
- `app/src/main/assets/builder.js`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonBridge.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/data/model/custom/DragonCardEditModel.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/edit/EditActivity.kt`

Những gì đã thay đổi
- `capturePNGForEdit()` trong `builder.js` gửi:
  + ảnh PNG
  + `selectionState = JSON.stringify(STATE.selections)`
- `DragonBridge.kt` nhận `EDIT_READY` và truyền thêm `selectionState` về native.
- `DragonWebViewActivity.kt` dùng `openEdit(dataUrl, selectionState)` để chuyển state sang màn edit.
- `DragonCardEditModel.kt` được bổ sung:
  + `selectionState: String = ""`
- `EditActivity.kt` đọc `selectionState` khi mở lại item cũ.
- Khi save lại item edit, `EditActivity.kt` cũng ghi ngược `selectionState` vào model.

Kết quả
- Dragon đã lưu có thể mở lại đúng part/màu trước đó.
- Luồng edit lại không còn chỉ phụ thuộc vào ảnh preview.

11. Trạng thái hiện tại của cụm WebView/assets

Hiện tại cụm này đã hỗ trợ
- Render Dragon builder bằng assets local.
- Chuyển tab giữa `head / torso / legs / wings / tail`.
- Random traits / random colors / random all.
- Focus item selected trong tab hiện tại sau random traits.
- Reset có xác nhận.
- Capture PNG để edit tiếp.
- Capture PNG để đi success ở luồng Dragon editor chính.
- Download-only ở nút Download của màn Trending.
- Truyền `selectionState` giữa JS và native.
- Mở lại item đã lưu với đúng state cũ.
- Chạy WebView ở chế độ nền trong suốt.
- Chạy assets ở chế độ preview-only ngay từ lúc HTML load.
- Giữ dialog loading đến khi render hoàn tất ở màn Trending.

13. Bổ sung mới nhất: khóa phạm vi random theo UI editor hiện có

Các file liên quan
- `app/src/main/assets/builder.js`

Những gì đã thay đổi
- `randomizeTraits()` không còn random toàn bộ `STATE.data.selects`.
- `randomizeColors()` không còn random toàn bộ `STATE.data.color_inputs`.
- Thay vào đó, `builder.js` lấy danh sách hợp lệ từ `CONFIG.TAB_ROWS`:
  + `getEditablePartIds()`
  + `getEditableColorIds()`
- Chỉ những `partId` và `colorId` có mặt trong UI editor hiện tại mới được random.

Lý do
- Trước đó random có thể chạm vào các select ẩn hoặc các field không có UI edit ở native.
- Kết quả là ảnh save ra vẫn đúng, nhưng khi mở lại để edit thì state có thể lệch hoặc gây lỗi vì editor không quản được hết các field đã bị random.

Kết quả mới
- Luồng `random -> save -> edit lại` ổn định hơn.
- Những gì bị random đều là những gì editor hiện tại có thể khôi phục và chỉnh tiếp.
