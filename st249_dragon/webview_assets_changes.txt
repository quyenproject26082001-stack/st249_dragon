Tổng hợp thay đổi từ trước đến nay của cụm Dragon WebView / assets
=================================================================

Phạm vi tài liệu
- Tài liệu này chỉ ghi lại các thay đổi liên quan đến WebView, JS, HTML, CSS và các file native bridge đi kèm.
- Trọng tâm là luồng Dragon builder, preview, random, edit, download và đồng bộ state.


1. Giai đoạn đầu: dựng Dragon builder bằng assets local

Các file chính
- `app/src/main/assets/index.html`
- `app/src/main/assets/style.css`
- `app/src/main/assets/builder.js`
- `app/src/main/assets/parts_config.json`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`

Những gì đã định hình
- Dùng `index.html` làm giao diện chính cho Dragon builder trong WebView.
- Giao diện ban đầu gồm:
  + top bar
  + preview area
  + action row
  + panel area
  + bottom tabs
- `style.css` phụ trách toàn bộ phần nhìn của WebView.
- `builder.js` là logic chính:
  + load dữ liệu
  + render panel theo tab
  + update preview
  + đổi style / đổi màu / random / reset
- `parts_config.json` chia part theo các tab `head`, `torso`, `legs`, `wings`, `tail`.
- `DragonWebViewActivity` dùng asset loader để load toàn bộ nội dung từ assets local.

13. Bổ sung mới nhất: khóa phạm vi random theo UI editor hiện có

Các file liên quan
- `app/src/main/assets/builder.js`

Những gì đã thay đổi
- `randomizeTraits()` không còn random toàn bộ `STATE.data.selects`.
- `randomizeColors()` không còn random toàn bộ `STATE.data.color_inputs`.
- Thay vào đó, `builder.js` lấy danh sách hợp lệ từ `CONFIG.TAB_ROWS`:
  + `getEditablePartIds()`
  + `getEditableColorIds()`
- Chỉ những `partId` và `colorId` có mặt trong UI editor hiện tại mới được random.

Lý do
- Trước đó random có thể chạm vào các select ẩn hoặc các field không có UI edit ở native.
- Kết quả là ảnh save ra vẫn đúng, nhưng khi mở lại để edit thì state có thể lệch hoặc gây lỗi vì editor không quản được hết các field đã bị random.

Kết quả mới
- Luồng `random -> save -> edit lại` ổn định hơn.
- Những gì bị random đều là những gì editor hiện tại có thể khôi phục và chỉnh tiếp.

14. Bổ sung mới nhất: lọc state khi edit từ màn Trending

Các file liên quan
- `app/src/main/assets/builder.js`
- `app/src/main/java/com/female/maker/oc/creator2/ui/trending/TrendingActivity.kt`

Những gì đã thay đổi
- `builder.js` thêm `serializeEditableSelections()`.
- `getEditablePartIds()` và `getEditableColorIds()` được chuẩn hóa bằng `Set` để bỏ trùng.
- `dispatch('GET_EDITABLE_STATE')` trả về đúng phần state mà editor native đang hỗ trợ:
  + các `partId` có `style`
  + các `colorId` có `color`
- `TrendingActivity.kt` không còn lấy `GET_STATE` đầy đủ khi bấm edit.
- Thay vào đó, màn Trending lấy `GET_EDITABLE_STATE` rồi mới mở `DragonWebViewActivity`.

Lý do
- Màn Trending chỉ cần chuyển sang editor với phần state có thể edit lại được.
- Việc truyền cả state full không giúp thêm gì cho luồng edit, nhưng tăng rủi ro mang theo dữ liệu thừa hoặc field không cần thiết.

Kết quả mới
- Luồng `Trending -> Edit` gọn hơn và ổn định hơn.
- Khi random rồi bấm edit, state đưa sang `DragonWebViewActivity` khớp đúng với phạm vi editor hiện tại quản lý.
15. Bổ sung mới nhất: apply state bằng batch khi mở editor

Các file liên quan
- `app/src/main/assets/builder.js`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`

Những gì đã thay đổi
- `builder.js` thêm action `APPLY_STATE`.
- `DragonWebViewActivity.kt` không còn loop từng item để gọi `SET_STYLE` / `SET_COLOR`.
- Khi nhận `selectionState`, native gửi một batch state duy nhất sang WebView.
- WebView merge state, render panel, focus item đang chọn và `updatePreview()` một lần.

Lý do
- Với state từ màn Trending sau `RANDOMIZE_ALL`, số lượng trait và màu khá nhiều.
- Gọi nhiều lệnh JS liên tiếp trong lúc editor mới load có thể làm WebView render chồng nhau, nặng và dễ gây thoát/crash trên máy yếu.

Kết quả mới
- Luồng `Trending -> random -> edit` nhẹ hơn khi mở `DragonWebViewActivity`.
- State random all vẫn được giữ, nhưng editor không render lặp hàng chục lần khi vừa vào màn.
16. Bổ sung mới nhất: update đúng item My Dragon khi save lại từ Dragon editor

Các file liên quan
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/my_creation/fragment/MyAvatarFragment.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/view/ViewActivity.kt`

Những gì đã thay đổi
- Thêm `DragonWebViewActivity.EXTRA_EDIT_MODEL_ID`.
- Khi edit từ icon trong `item_my_album`, `MyAvatarFragment.kt` truyền thêm `DragonCardEditModel.id`.
- Khi edit từ `ViewActivity`, cũng truyền thêm `DragonCardEditModel.id`.
- `DragonWebViewActivity.registerSavedDragon()` ưu tiên tìm item cũ bằng `id`.
- Nếu không có `id`, mới fallback về `previewPath` như trước.
- Sau khi save, `DragonWebViewActivity` cập nhật lại `editModelId` và `editSourcePath` theo model mới.

Lý do
- `previewPath` là đường dẫn ảnh PNG và sẽ đổi sau mỗi lần save.
- Dùng `previewPath` làm khóa update không đủ bền, nhất là khi màn editor cũ vẫn còn giữ path cũ.

Kết quả mới
- Edit item từ My Dragon rồi save sẽ replace đúng item cũ.
- Không bị add nhầm thành item mới hoặc giữ item cũ không đổi do path đã thay đổi.
17. Bổ sung mới nhất: giữ đúng con rồng khi đi từ Dragon editor sang EditActivity

Các file liên quan
- `app/src/main/java/com/female/maker/oc/creator2/core/utils/key/IntentKey.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/edit/EditActivity.kt`

Những gì đã thay đổi
- Thêm `IntentKey.EDIT_MODEL_ID`.
- `DragonWebViewActivity.openEdit()` truyền `EDIT_MODEL_ID` sang `EditActivity` nếu đang edit một item My Dragon cũ.
- `EditActivity.restoreState()` đọc `EDIT_MODEL_ID` và tìm model theo `id` trước, sau đó mới fallback theo `previewPath`.
- Khi đi từ Dragon editor sang EditActivity, `EditActivity` ưu tiên ảnh rồng mới từ intent (`EDIT_IMAGE_PATH`) thay vì dùng lại `dragonImagePath` cũ trong model.
- `selectionState` mới từ Dragon editor cũng được ưu tiên, chỉ dùng state cũ khi intent không có state mới.

Lý do
- Sau khi chỉnh trait/màu ở Dragon editor, ảnh rồng mới được truyền sang `EditActivity`.
- Nếu `EditActivity` ưu tiên `savedModel.dragonImagePath` cũ thì card editor sẽ hiện lại con rồng cũ, dù user vừa sửa xong.

Kết quả mới
- Luồng `My Dragon -> Dragon editor -> Save/Edit card -> EditActivity` giữ đúng con rồng vừa chỉnh.
- Khi save ở `EditActivity`, model cũ vẫn được replace đúng nhờ `id`, không tạo item sai.
18. Bổ sung mới nhất: sửa trường hợp edit save nhưng nhìn như không đổi

Các file liên quan
- `app/src/main/java/com/female/maker/oc/creator2/ui/edit/EditActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/my_creation/fragment/MyAvatarFragment.kt`
- `app/src/main/java/com/female/maker/oc/creator2/ui/view/ViewActivity.kt`

Những gì đã thay đổi
- `EditActivity.restoreState()` chỉ ưu tiên `EDIT_IMAGE_PATH` làm ảnh rồng mới khi có `EDIT_SELECTION_STATE` mới từ Dragon editor.
- Nếu mở thẳng `EditActivity` từ My Dragon/View, ảnh rồng thuần vẫn lấy từ `savedModel.dragonImagePath`, không lấy nhầm ảnh card preview.
- Nhánh mở thẳng `EditActivity` từ `MyAvatarFragment` và `ViewActivity` truyền thêm `EDIT_MODEL_ID` nếu item là Dragon card.
- File PNG save từ `DragonWebViewActivity` và `EditActivity` dùng timestamp có millisecond để tránh ghi đè nếu save nhanh trong cùng một giây.

Lý do
- Có 2 loại ảnh khác nhau:
  + ảnh rồng thuần từ Dragon editor
  + ảnh card preview từ EditActivity
- Nếu nhầm 2 ảnh này, màn edit có thể restore sai ảnh và khi save lại nhìn như không thay đổi.

Kết quả mới
- Edit từ My Dragon/View rồi save sẽ update đúng item cũ bằng `id`.
- Đi từ Dragon editor sang EditActivity sẽ dùng đúng con rồng vừa chỉnh.
- Mở thẳng EditActivity từ card cũ sẽ không lấy nhầm ảnh card làm ảnh rồng bên trong.
19. Bổ sung mới nhất: bấm Save ở màn Dragon là update item ngay

Các file liên quan
- `app/src/main/java/com/female/maker/oc/creator2/ui/dragon_webview/DragonWebViewActivity.kt`

Những gì đã thay đổi
- `DragonWebViewActivity.openEdit()` không còn chỉ lưu ảnh cache rồi mở `EditActivity`.
- Khi bấm Save/Edit từ màn Dragon, app lưu ảnh rồng vào thư mục album và ghi/update `DragonCardEditModel` ngay lập tức.
- Nếu đang edit item cũ:
  + giữ nguyên `previewPath` card cũ
  + cập nhật `dragonImagePath` bằng ảnh rồng mới
  + cập nhật `selectionState` mới
  + giữ lại name tag, describe, power, background cũ
